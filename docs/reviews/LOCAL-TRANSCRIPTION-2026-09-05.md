# Local Parakeet transcription: implementation and privacy review

Date: 2026-09-05. Result: **ready for owner use on this development machine** under the approved session-only OD-03 exception. This is not an installer or public-release qualification.

## Delivered

Ascend's existing Electron shell now offers a native recording chooser, English Parakeet transcription, processed-audio progress, cancellation, selectable paragraph-formatted transcript text, deliberate UTF-8 TXT export and Clear. Supported containers are WAV, MP3, M4A/AAC, FLAC and MP4. One instance, one job and one model run at a time. There is no account, API key, HTTP worker, cloud fallback, database/history or automatic audio/transcript save.

The main process owns the selected read-only file handle. The sandboxed renderer gets an opaque token. Python receives only bounded byte-range responses through inherited private pipes, never an audio path or URL. The decoder uses a file object, restricts formats/codecs/protocols, resamples incrementally and checks metadata plus actual decoded samples. Exactly 115,200,000 samples at 16 kHz is accepted; an additional sample fails visibly. Inference windows never exceed 30 seconds and retain context around joins. Whole words are assigned by token timestamps, preserving legitimate repetition.

## Sentence-aligned paragraphs — 2026-09-05

The owner's paragraph request is implemented entirely in the existing offline worker. Whole-word reconstruction retains the same ownership rule and now also carries the first/last token time. A small streaming formatter inserts one blank line after the first recognized sentence ending at or beyond roughly 30 seconds from the paragraph's first word. Common abbreviations, initials/acronyms, decimals and ellipses are handled conservatively; closing quotes/brackets stay attached. No artificial sentence ending or rewritten word is added. An unpunctuated sentence can exceed 30 seconds. Formatting does not fix the separately observed recognition losses at some inference boundaries.

The worker emits append-only text fragments with their joining whitespace; the shell concatenates them exactly. This preserves a sentence across inference windows and preserves paragraph breaks across progress events, cancellation and TXT export. Formatter state is constant-size, apart from the bounded current word/fragment list; it introduces no model, network call, retained history or additional permission. The new pure-Python file inherits the existing package-specific read/execute ACL. Transcript rendering remains `textContent` with `white-space: pre-wrap`, so recognition output is never executable HTML.

## Enforced privacy and observed limits

The worker is a Windows **AppContainer with zero capabilities**, checked again from its real process token. The launcher grants its specific package SID read/execute access to the runtime, model and needed code; it grants no user recording directory. The child cannot create subprocesses. Its Job Object is killed when the supervisor closes, and the supervisor watches the Electron parent handle. Environment inheritance excludes API keys, service credentials and arbitrary Python paths.

Native `CreateFileW` tests denied an unrelated synthetic private file and creation inside the read-only model directory. Real Winsock outbound IPv4 connection attempts returned **WSAEACCES 10013**. The loopback attempt timed out and IPv6 had no route; those two results alone are not proof of a specific firewall rejection. Zero network capabilities enforce the network boundary without changing machine-wide firewall settings or disconnecting other apps. Microsoft's documented boundary: [AppContainer isolation](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer).

The worker additionally audits and denies Python socket operations, content-file writes and subprocess execution; the Windows null device is allowed for discarded diagnostics. The real model load/inference probe observed zero Python network/content-write attempts. Twenty-eight TCP-table samples during the long UI run observed zero worker endpoints. The AppContainer profile contained no files after the runs. **An exhaustive native network-call trace was not collected**: sampled endpoints and Python auditing cannot establish that no native call was ever attempted. Native networking remains OS-denied regardless. No claim of whole-system or malicious-kernel isolation is made.

The renderer uses a nonpersistent partition, disabled cache, a strict CSP and denied external session requests. No crash reporting or telemetry upload is started. Native worker diagnostics are discarded; protocol errors use fixed codes. There are no temporary decoded audio files. Source changes fail the job. TXT export checks the opened target's file identity before truncating, preventing overwrite of the recording through an alias/hard link. Explicit export remains plain text; choosing a synchronized destination may let that destination's software upload it.

Managed memory is not guaranteed to be zeroized, and Windows paging, hibernation, crash dumps and same-user malware are outside this guarantee. AppContainer is a standard Windows sandbox, not protection from a compromised operating system. The model does not reliably detect language or guarantee exact transcription. Broader meeting diversity, all supported hardware and clean-machine installation are untested. Existing installer/development dependency audit findings and signing/release gates remain open; no redistribution is approved by this work.

## Review findings resolved

The review corrected Windows console-child startup under the one-process job limit by using the already-installed `pythonw.exe`; replaced dependency cache hard links with isolated copies for reliable package ACLs; added actual CUDA-session checks; rejected network drives; protected the source from export aliases; rejected stale worker events; handled cancellation/partial results; and added parent-death supervision. Transcript text uses `textContent`, never HTML. Setup downloads remain in a separate explicit script and never run during transcription.

Initial acceptance used public/synthetic recordings. Later owner-authorized comparisons and paragraph verification used the specific owner-selected test recording. No owner audio, transcript or screenshot is included in repository source. Owner-selected sensitive audio remains within the approved stateless exception; retained histories and other Ascend features still require their own gates.
